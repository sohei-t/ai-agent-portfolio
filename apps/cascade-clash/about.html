📋 プロジェクト概要

📋 Project Overview

Cascade Clash は、プレイヤーと CPU が同じ画面で連鎖パズルを戦わせる対戦型ゲームです。 自分のフィールドで連鎖を組みつつ、相手フィールドの CPU が繰り出す一手を見て、 削り合いのタイミングを読む駆け引きが楽しめます。

要件定義から実装・テスト・ドキュメント生成まで、Claude Code の AIエージェントシステムが 一貫して開発を担当しました。実行時の外部依存ゼロ、音・画像とも外部素材や課金APIを使わずに 完成させています。

Cascade Clash pits you against a CPU opponent in a real-time chain-puzzle duel on a shared screen. Build your own cascades while reading the CPU's moves on the opposing field, timing your attacks and counters to outscore your rival.

The entire project — requirements, implementation, testing, and documentation — was built end to end by Claude Code's AI agent system, with zero runtime dependencies and no paid APIs for audio or art.

🧮 スコア・ブロッカーの数値仕様

🧮 Scoring & Blocker Formulas

2026-07-11 のユーザーフィードバックにより、旧来の基本点テーブル方式から 通(Tsu)式のレバレッジ攻撃システムへ全面改訂しました （リサーチ出典: Puyo Nexus Wiki の Scoring / Nuisance queue 記事。数値・テーブルは本プロジェクト独自定義です）。 

段スコア = (10 × その段の消去数) × clamp(連鎖パワー + 色ボーナス + グループボーナス, 1, 999)
攻撃ポイント = 段スコア合計 + 繰り越し
送信ブロッカー数 = floor(攻撃ポイント ÷ 70)（端数は次回へ繰り越し）
  • 連鎖パワー: 段数に応じたレバレッジ曲線 [0, 8, 16, 32, 64, 96, 128, 160, ...]（6段目以降は+32ずつ）
  • 1回投下の上限: 相手盤面へ1回で降下するブロッカーは最大30個（超過分はキューに残留）
  • 相殺: 自分の新規攻撃ポイントは、まず相手からの送信待ちブロッカーとの相殺に充当される

Following user feedback on 2026-07-11, scoring was fully revised from the old base-point table into a Tsu-style leverage attack system (research source: the Puyo Nexus Wiki Scoring / Nuisance queue articles; all numbers and tables here are this project's own original definitions). 

step score = (10 x cells cleared this step) x clamp(chain power + color bonus + group bonus, 1, 999)
attack points = sum of step scores + carryover
blockers sent = floor(attack points / 70)  (remainder carries over)
  • Chain power: a leverage curve by chain depth [0, 8, 16, 32, 64, 96, 128, 160, ...] (+32 per step from step 6 on)
  • Per-drop cap: at most 30 blockers actually fall per drop event (overflow stays queued)
  • Offset: your new attack points are first applied to cancel the opponent's pending attack on you

🧠 CPUアルゴリズム

🧠 CPU Algorithm

CPU は探索木を使う minimax 型ではなく、盤面候補を仮想シミュレーションし、 重み付き評価関数でスコアリングする方式を採用しています。

  • 候補生成: 列とピース回転の組み合わせ（最大22候補程度）を仮想的に落下させ、着地形を算出
  • 評価関数: 消去数スコア・連鎖予測スコア・高さペナルティ・凹凸ペナルティ・危険度ペナルティを加重合算
  • 非ブロッキング思考: 候補評価を複数フレームに分割して実行し、思考中も自分の描画・入力処理を止めない
  • 難易度差: 初級はノイズと誤選択率を大きく、上級はノイズ0・即断の高速思考に調整

Rather than a minimax search tree, the CPU uses a candidate simulation + weighted evaluation-function approach.

  • Candidate generation: virtually drops each column/rotation combination (up to ~22 candidates) to compute the resulting board
  • Evaluation function: weighted sum of clear-count, predicted-chain, height penalty, bumpiness penalty, and danger-line penalty
  • Non-blocking thinking: candidate evaluation is spread across multiple frames so rendering/input never stalls
  • Difficulty tuning: Easy adds noise and a mis-pick chance; Hard runs near-zero noise with fast, decisive picks
